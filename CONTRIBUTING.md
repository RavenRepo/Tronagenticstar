## Code of Conduct

Please be respectful and constructive in all interactions. We are committed to providing a welcoming and inclusive environment for all contributors.

## Getting Started

1. Fork the repository
2. Clone your fork locally
3. Set up the development environment (see README.md)
4. Create a new branch for your feature or fix

## How to Contribute

### Reporting Issues

- Search existing issues before creating a new one
- Use descriptive titles and provide detailed information
- Include steps to reproduce for bugs
- Add relevant labels when possible

### Submitting Changes

1. Create a feature branch from `main`
2. Make your changes following our coding standards
3. Write or update tests as needed
4. Ensure all tests pass
5. Submit a pull request

## License Headers

This project is licensed under the MIT License. When creating new source files, you may optionally include a license header. If you choose to include one, use the following format:

### For JavaScript/TypeScript files:

```javascript
/**
 * Copyright (c) 2024 Constella Contributors
 * SPDX-License-Identifier: MIT
 */
```

### For Python files:

```python
# Copyright (c) 2024 Constella Contributors
# SPDX-License-Identifier: MIT
```

### For Shell scripts:

```bash
#!/bin/bash
# Copyright (c) 2024 Constella Contributors
# SPDX-License-Identifier: MIT
```

### For CSS/SCSS files:

```css
/**
 * Copyright (c) 2024 Constella Contributors
 * SPDX-License-Identifier: MIT
 */
```

**Note:** License headers are optional for this project. The MIT License in the root LICENSE file covers all contributions.

## Pull Request Process

1. Update documentation if your changes affect user-facing features
2. Ensure your code follows the existing style conventions
3. Write meaningful commit messages
4. Reference any related issues in your PR description
5. Request review from maintainers

### Commit Message Format

Use clear, descriptive commit messages:

```
type(scope): brief description

Longer description if needed.

Fixes #123
```

Types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

## Development Guidelines

### Code Style

- Follow existing patterns in the codebase
- Use meaningful variable and function names
- Add comments for complex logic
- Keep functions focused and modular

### Testing

- Write tests for new features
- Ensure existing tests pass before submitting
- Aim for meaningful test coverage

### Documentation

- Update README.md for user-facing changes
- Add inline documentation for public APIs
- Keep documentation current with code changes

## Questions?

If you have questions about contributing, please open an issue for discussion.
