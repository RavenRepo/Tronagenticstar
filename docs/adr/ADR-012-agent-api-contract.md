# ADR-012: Specialist Agent API Contract

**Date**: 2025-08-01

**Status**: Proposed

## Context

With the adoption of a TypeScript-based `ChiefArchitect` as the master orchestrator (ADR-011), we need a standardized, language-agnostic communication protocol for the orchestrator to manage and interact with the fleet of specialist agents (implemented in Python and potentially other languages). A well-defined API contract is essential for interoperability, scalability, and system-wide health monitoring.

## Decision

All specialist agents MUST implement a RESTful HTTP API that adheres to the following contract. The `ChiefArchitect` will use this API for all inter-agent communication.

### 1. Authentication

*   All requests from the `ChiefArchitect` to a specialist agent will include an `Authorization` header with a Bearer token.
*   `Authorization: Bearer <JWT_TOKEN>`
*   The JWT token will be generated by the `ChiefArchitect`'s `AgentAuthenticator` upon agent registration and will contain the `agent_id` and its `capabilities`.
*   Specialist agents are responsible for validating this token to ensure the request is from a legitimate orchestrator.

### 2. API Endpoints

All specialist agents MUST implement the following three endpoints:

#### 2.1. Health Check

*   **Endpoint**: `GET /health`
*   **Purpose**: Allows the `ChiefArchitect` to perform regular health checks.
*   **Request Body**: None
*   **Success Response (200 OK)**:
    ```json
    {
      "status": "ok" | "degraded",
      "details": "Optional string providing more context"
    }
    ```
*   **Error Response (503 Service Unavailable)**: If the agent is unhealthy and cannot process requests.

#### 2.2. Get Capabilities

*   **Endpoint**: `GET /capabilities`
*   **Purpose**: Allows the `ChiefArchitect` to discover the agent's capabilities upon registration or for periodic validation.
*   **Request Body**: None
*   **Success Response (200 OK)**:
    ```json
    {
      "agent_id": "string",
      "agent_type": "string (e.g., 'specialist', 'guardian')",
      "task_type": "string (e.g., 'CODE_GENERATION', 'SECURITY_SCAN')",
      "capabilities": [
        "string (e.g., 'generate_react_component', 'scan_for_xss')"
      ]
    }
    ```

#### 2.3. Execute Task

*   **Endpoint**: `POST /execute_task`
*   **Purpose**: The primary endpoint for the `ChiefArchitect` to assign a task to the agent.
*   **Request Body** (`Task` object):
    ```json
    {
      "task_id": "string (UUID)",
      "task_type": "string",
      "parameters": {
        "key": "value"
      },
      "context": [
        {
          "id": "string",
          "agentId": "string",
          "timestamp": "string (ISO 8601)",
          "content": {},
          "tags": ["string"],
          "metadata": {}
        }
      ]
    }
    ```
*   **Success Response (200 OK)** (`TaskResult` object):
    ```json
    {
      "task_id": "string (UUID)",
      "status": "completed",
      "result": {
        "key": "value"
      },
      "metrics": {
        "processing_time_ms": "number",
        "tokens_used": "number (optional)"
      }
    }
    ```
*   **Error Response (422 Unprocessable Entity)**: If the task payload is invalid.
*   **Error Response (500 Internal Server Error)**: If the agent fails to process the task.

## Consequences

### Positive:

*   **Standardization**: Provides a clear, consistent interface for all agents, simplifying integration and development.
*   **Interoperability**: Enables seamless communication between the TypeScript orchestrator and Python agents.
*   **Scalability**: New agents can be added to the system easily by adhering to this contract.
*   **Testability**: Both the orchestrator and the agents can be tested independently against this contract.

### Negative:

*   **Implementation Overhead**: All existing Python services must be refactored to expose these specific endpoints.
*   **Rigidity**: The contract creates a degree of rigidity. Changes to the core task structure will require updates across all agents.

## Next Steps

1.  **Update Python Services**: Refactor all services in the `services/` directory (`codecraft`, `evaluator`, etc.) to implement this API contract. This includes adding a web server (like FastAPI) if they don't already have one.
2.  **Update `FrameworkRouter`**: Modify the `FrameworkRouter` in the TypeScript orchestrator to make HTTP POST requests to the `/execute_task` endpoint of the selected agent.
3.  **Implement Health Checks**: The `ChiefArchitect`'s health check mechanism should be updated to poll the `/health` endpoint of all registered agents.
4.  **Update Agent Registration**: The agent registration process should now involve the `ChiefArchitect` calling the `/capabilities` endpoint to verify the agent's self-reported abilities.
